# CopyRecipe 設計書

## コンセプト

> **「動画を巻き戻さずに、材料と工程を一目で確認しながら料理できる」**

- **使う場面**：キッチンで料理している最中。手が濡れていたり汚れていたりして、スマホは少し離れた場所に置いてある。
- **中心となる価値**：材料と工程が、1つの画面で、離れた場所からでも読める形で並んでいること。
- **やらないこと**：レシピの検索・発見や SNS 的な共有（YouTube 自体が担う）。レシピの手での編集、ステップモード、人数換算、材料・工程のチェック（「方針の変更」を参照）。

工程の情報源は「概要欄からの抽出＋チャプター」とし、料理中に見る画面の完成度を優先する。字幕や AI 要約による工程生成は後で別途検討する。

---

## 1. 全体の流れ

```
URL入力 ─▶ YouTube API ─▶ 概要欄（生テキスト）
                               │
                               ▼
                       抽出処理（純粋なDart関数）
                       ├─ 材料の抽出
                       ├─ 工程の抽出
                       └─ チャプターの抽出
                               │
                               ▼
                    Recipe（構造化データ）──▶ Hive に保存
                               │
                      ┌────────┴────────┐
                      ▼                 ▼
                  レシピ一覧     料理中画面（中心）
```

**設計の原則**

- **概要欄の原文は必ず保存する**。抽出処理を改良したら、保存済みのレシピにも再抽出をかけられる。
- **抽出処理は UI や API に依存しない純粋な関数にする**。実際の概要欄のテキストを使ったテストだけで精度を上げていける。
- **抽出結果は常に原文から作り直せる状態にしておく**。編集機能は廃止したので、廃止前に手で直したレシピ（`isEdited`）も起動時に一度だけ抽出し直す。

## 2. データモデル

```dart
@HiveType(typeId: 1)
class Recipe {
  @HiveField(0) final String videoId;
  @HiveField(1) final String title;
  @HiveField(2) final String channelTitle;
  @HiveField(3) final String? thumbnailUrl;     // 非公開・削除済みの動画を考慮して null も許す
  @HiveField(4) final String rawDescription;    // 概要欄の原文（再抽出用）
  @HiveField(5) final List<Ingredient> ingredients;
  @HiveField(6) final List<RecipeStep> steps;
  @HiveField(7) final String? servings;         // 「2人分」など（原文のまま）
  @HiveField(8) final DateTime addedAt;         // 一覧の並び順に使う
  @HiveField(9) final bool isEdited;            // 編集機能の廃止前に手で直したレシピの印。起動時に抽出し直して false に戻す
  @HiveField(10) final int parserVersion;       // どの版の抽出処理で作ったか
}

@HiveType(typeId: 2)
class Ingredient {
  @HiveField(0) final String name;     // 「豚バラ肉」
  @HiveField(1) final String? amount;  // 「200g」「大さじ1」（分量の換算は後で実装）
  @HiveField(2) final String? group;   // 「A」「タレ」など。見出しごとにまとめて表示する
}

@HiveType(typeId: 3)
class RecipeStep {
  @HiveField(0) final String text;
  @HiveField(1) final int? startSeconds; // チャプターと対応できた場合の動画の開始時刻
}
```

- **分量は文字列のまま持つ**。数値と単位への分解はしない（人数換算はやらない）。

## 3. 抽出処理

`lib/parser/` に、段階ごとの関数として置く。

```
normalize()        改行コードと全角／半角の表記をそろえる
  ▼
splitSections()    見出しを見つけて「材料」「作り方」「チャプター」「その他」に分ける
  ▼
parseIngredients() 1行を「材料名＋分量」に分け、【A】や★タレなどのグループ見出しも認識する
parseSteps()       「1.」「①」「(1)」「STEP1」などの番号付きの行、または作り方見出しの後の行
parseChapters()    「0:00 オープニング」形式のタイムスタンプ行
  ▼
mergeStepsWithChapters()
```

| 処理 | 判定ルール（最初の版） |
|---|---|
| 材料の見出し | `材料`、`【材料】`、`■材料`、`◆材料`、`○人分` |
| 作り方の見出し | `作り方`、`手順`、`工程`、`How to` |
| 材料と分量の区切り | 連続する空白、全角スペース、`…`、`・・・`、`：`、タブ、`......` |
| 分量っぽい文字列 | `大さじ`、`小さじ`、`g`、`ml`、`cc`、`個`、`本`、`枚`、`片`、`かけ`、`少々`、`適量`、数字、分数 |
| 抽出をやめる行 | SNS、提供、チャンネル登録などのフッター |

**工程とチャプターの組み合わせ方**

- **工程もチャプターもある場合**：見出しの文言が似ていれば工程に開始時刻を付ける（できなければ時刻なし）。
- **工程がなくチャプターだけある場合**：チャプターを工程として使う。「オープニング」「試食」「完成」「エンディング」などは除外する。
- **どちらもない場合**：工程は空のまま。画面に「工程が見つかりませんでした」と表示し、概要欄の全文や動画で確認するよう案内する。

登録時の判定は抽出結果で 1 本ずつ行い、材料が見つからない動画は保存しない。

**テスト**：`test/parser/fixtures/*.txt` に概要欄のサンプルを置き、期待する結果と比較する。

## 4. 画面

### 4-1. 料理中画面（中心となる画面）

```
┌─────────────────────────────┐
│ ←  豚バラ大根の煮物       A± │  文字サイズの切り替え
├─────────────────────────────┤
│ [サムネイル小]  2人分         │
│                              │
│ ■ 材料              [コピー] │
│ 豚バラ肉 ············· 200g  │
│ 大根 ··············· 1/3本  │
│  A                           │
│ 醤油 ·············· 大さじ2  │
│ みりん ············ 大さじ2  │
│                              │
│ ■ 作り方                     │
│ ① 大根を2cm幅に切る    ▶1:12│  ▶ を押すと動画のその時刻へ
│ ② 豚肉を炒める         ▶2:40│
│ ③ Aを加えて20分煮る    ▶3:55│
│                              │
│ ▸ 概要欄の全文                │  最初は折りたたんでおく
└─────────────────────────────┘
```

- 画面を開いている間は `wakelock_plus` でスリープしないようにする。
- 文字サイズは 3 段階で切り替え、選んだサイズは端末に保存する。
- MVP では `url_launcher` で `https://youtu.be/{id}?t={秒}` を開く。
- 材料をまとめてクリップボードにコピーできる。本文は `SelectableText` にする。
- 材料・工程がないときは「見つかりませんでした」と表示し、概要欄の全文や動画で確認するよう案内する。

### 4-2. 一覧と登録

- 一覧は `addedAt` の新しい順。サムネイルには読み込み中と失敗時の表示を付ける。スワイプ削除後は SnackBar に「元に戻す」を出す。
- 追加は右下のボタンから開くシートで行う（URL 用のキーボード、クリップボードからの貼り付け）。
- 1 本だけ登録した場合はそのまま料理中画面へ移る。再生リストの場合は「12本中9本を登録しました（3本はレシピが見つかりませんでした）」のように結果を表示する。

## 6. 既存データの移行

- 新しいデータは別の Box（`recipes`）に保存し、typeId は 1〜3 を使う（既存の `Video` は typeId 0）。
- 起動時に古い `Videos` Box が残っていれば、各動画の `description` に抽出処理をかけて `Recipe` に変換し、終わったら古い Box を削除する。

### 進捗メモ

- Phase 1・2 は実装済み（PR #21・#22）。
- Phase 3 の実装での判断
  - 概要欄の全文を編集する画面は廃止し、材料・作り方・人数を個別に編集する画面（`RecipeEditScreen`）に置き換えた。「自動抽出に戻す」で原文から抽出し直せる。
  - ステップモードは PageView で実装し、タップ（右半分で次へ・左半分で前へ）とスワイプの両方で移動できる。「次へ」で進んだ工程は完了としてチェックする。
  - 抽出処理を版 2 に上げた（小文字のグループ記号「a. 砂糖」、「下ごしらえ」「下準備」の見出し、番号付き工程の前の行を独立した工程として扱う）。手で直していないレシピは起動時に抽出し直される。
  - `RecipeRepository` をインターフェースにし、ウィジェットテストではメモリ上の実装を使う（疑似時間の中で Hive の書き込みが終わらず、テストが止まるため）。

### 方針の変更（2026-11-21）

- **人数換算はやらない**。大さじ・個数などの書き方は動画ごとの揺れが大きく、数値だけを掛け算し直しても正しく読める表示にならないため（PR #25 は取り下げ）。
- **ステップモードはやめる**。料理中画面の一覧で足りるため、画面を 1 つに絞る（当時あった材料・工程のチェックも、のちに削除した）。
- **レシピの編集機能はやめる**。抽出に失敗したときは、料理中画面の「概要欄の全文」と動画で確認する。抽出の精度は抽出処理の改良で上げる。
- `Recipe.isEdited` は Hive の保存形式を変えないために残す。廃止前に手で直したレシピは、編集も「自動抽出に戻す」もできないまま改良が届かなくなるのを避けるため、起動時に一度だけ原文から抽出し直す（手で直した内容は失われる）。

### UI の見直し（2026-11-21）

「キッチンで離れた場所から一目で読める」を基準に、画面の見た目と操作を見直した。

- **配色をテーマにまとめた**（`lib/app/theme.dart`）。トマト色を基調色にし、`ColorScheme.fromSeed` の `fidelity` で色味を保つ。画面ごとの色の直書き（AppBar の黄色、カードの肌色など）をやめ、ダークモードにも対応した。
- **材料の分量を右端にそろえ、材料名との間を点線でつないだ**。行ごとに分量の位置がばらつかず、材料名から分量へ目で追える。材料名は行の幅の 42%、分量は 50% までで折り返す。
- **工程番号を丸い札にし、見出しの「■」を基調色の縦線に変えた**。料理中画面の AppBar のタイトルは、本文の大きなタイトルと重複するので外した。
- **追加の入口を、下のタブから右下のボタン（FAB）とシートに変えた**。入力欄は URL 用のキーボードにして日本語入力の変換待ちを避け、クリップボードから貼り付けるボタンを付けた。エラーはシートの中に出す。
- **一覧のカード**は、タイトルを 2 行・15pt にし、チャンネル名と「材料 8 · 工程 4 · 2人分」の概要を加えた。タップの反応（波紋）を付け、削除は左スワイプだけにした。レシピがないときは案内と追加ボタンを出す。

### チェック機能の削除（2026-11-21）

- **材料・工程のチェックをやめる**。料理中画面は読むための画面に絞り、行のタップでのチェック、チェック済みの行を薄くする表示、「すべてのチェックを外す」ボタンを削除した。
- 行の高さ（52pt 以上）は、離れた場所から行の区切りが分かるよう残す。チェックボックスの分だけ材料名・分量・工程の文字に使える幅が広がった。

### 材料での絞り込み・メニュー・アイコン（2026-11-23）

- **一覧を材料名で絞り込めるようにした**（#18）。一覧の上の入力欄に入れた語を空白で区切り、すべてを材料名の一部に含むレシピだけを出す。全角・半角、大文字・小文字、カタカナ・ひらがなの違いは無視する（漢字との表記の揺れは扱わない）。処理は `lib/features/recipe_list/ingredient_filter.dart` の純粋な関数。
- **一覧の AppBar に「使い方」「ライセンス」のメニューを付けた**（#9・#10）。使い方は README にも書いた。
- **アプリアイコンを、トマト色の背景に白いレシピカードと再生ボタンを重ねた図柄にした**（#20）。`tool/make_icon.py` で描き、`flutter_launcher_icons` で各サイズを作る。
